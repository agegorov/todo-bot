# Todo Bot — юзкейсы

Составлено по коду (`internal/bot`, `internal/api`, `internal/parser`, `internal/auth`, `internal/recurrence`, `internal/scheduler`, `web/`). Кратко, без описания UI-вёрстки.

## Telegram-бот

| UC | Триггер | Что происходит |
|----|---------|-----------------|
| Создать задачу текстом | Любое сообщение без `/` | NLP-парсинг (дата/время/тег/приоритет/проект/делегат/повтор) → задача в TO DO, тег `#telegram` авто |
| Создать задачу голосом | Voice-сообщение | Скачивание → ffmpeg OGG→WAV → whisper.cpp → текст → та же логика создания |
| `/list` | команда | Открытые задачи в scope отправителя: если TG привязан — задачи его веб-аккаунта, иначе только собственные orphan-задачи (созданные этим же TG-юзером до `/link`) |
| `/today` | команда | То же, но с дедлайном в следующие 24ч |
| `/overdue` | команда | То же, но просроченные |
| `/done <id>` | команда | Если TG привязан — перенос в Done-колонку веб-аккаунта + возможный спавн следующей итерации; если не привязан — закрывает только свою orphan-задачу (проверка `user_id IS NULL AND telegram_user_id = <sender>`), иначе «задача не найдена» |
| `/projects` | команда | Список проектов (Inbox/Work/Home/Personal) |
| `/link <token>` | команда | Привязка TG-аккаунта к веб-юзеру по токену из веба, забирает orphan-задачи |
| `/start`, `/help` | команда | Текст помощи |
| Напоминание | cron, каждую минуту | За 1 час до дедлайна шлёт сообщение в чат, куда доставим: telegram_id привязанного веб-аккаунта задачи, иначе telegram_user_id самой задачи; если у владельца нет Telegram — не отправляется, но помечается как отправленное |
| Еженедельный дайджест | cron, пятница 18:00 | Отдельное сообщение каждому привязанному к Telegram пользователю с числом его просроченных задач (0 — «просроченных нет») |

## Веб (канбан)

| UC | Что делает |
|----|-----------|
| Вход через Google | OAuth → создание/обновление юзера, авто-claim orphan-данных, сессия на 30 дней |
| Выход | Удаление сессии, редирект на `/login` |
| Просмотр доски — «По колонкам» | Карточки по своим колонкам, drag&drop между колонками |
| Просмотр доски — «По тегам» | Группировка задач по тегам, включая «без тега» |
| Фильтр по тегу | Клик по чипу тега — сужает список задач |
| Создать задачу текстом (веб) | Тот же NLP-парсер, что в боте, без авто-тега `#telegram` |
| Редактировать задачу | Модалка: title, notes, priority, deadline (date+time picker), tags, recurrence |
| Быстро закрыть задачу | Кнопка ✓ на карточке → Done-колонка, спавн повторной задачи если recurring |
| Удалить задачу | Крестик на карточке |
| Перетащить карточку между колонками | Drag&drop, авто `done_at` при попадании в Done-колонку и обратно при выносе |
| Создать колонку | Кастомная колонка с именем и цветом |
| Переименовать/перекрасить колонку | Через модалку редактирования |
| Удалить колонку | Только не системную (TO DO/Done защищены), с переносом задач |
| Переупорядочить колонки | Drag&drop заголовков колонок |
| Сменить тему | dark/light, сохраняется в `localStorage`, событие `themechange` для timepicker |
| Сгенерировать токен привязки Telegram | `/api/link/telegram` → показывает `/link <token>` для отправки боту |
| Получить текущего пользователя | `/api/me` — имя, email, аватар, статус привязки TG |

## Общая логика (фон)

| UC | Описание |
|----|----------|
| NLP-парсинг русского текста | Даты (сегодня/завтра/послезавтра/день недели/«15 мая»), время («в 18:30»), теги (`#тег`), приоритет (срочно→1, «когда-нибудь»→3), проект по ключевым словам или тегу, делегирование («попросить Х»), периодичность («каждый день/понедельник/...») |
| Периодические задачи | При закрытии recurring-задачи — спавн следующей от старого дедлайна (не от даты завершения), с доматыванием в будущее, переносом тегов/приоритета/проекта, новым напоминанием |
| Привязка TG↔веб | Одноразовый токен (15 мин) из веба → `/link` в боте → перенос всех orphan-задач этого TG-юзера на веб-аккаунт |
| Orphan-задачи | Задача от непривязанного TG-юзера создаётся без `user_id`, не видна на доске, ждёт `/link` |

## Исправлено (было в «Замечаниях», топ-1 из плана улучшений)

- Owner-гейт в `internal/bot/bot.go` снят — бот принимает сообщения от любого Telegram-юзера, как и было описано в CLAUDE.md, но не соответствовало коду. `TELEGRAM_OWNER_ID` убран из `.env`/`main.go`.
- `/list`, `/today`, `/overdue` теперь фильтруют по scope отправителя (см. таблицу выше), а не отдают задачи всех пользователей подряд.
- `/done <id>` для непривязанного TG-юзера проверяет владение orphan-задачей (`CompleteOrphanTaskForTelegram`) — иначе после снятия owner-гейта любой смог бы закрыть чужую задачу, подобрав id.
- Напоминания и еженедельный дайджест теперь адресные: летят в чат владельца конкретной задачи/пользователя, а не в чат единственного владельца бота. Заодно исправлен баг форматирования дайджеста (счётчик > 9 портил сообщение — было `string(rune('0'+n))` вместо `fmt.Sprintf("%d", n)`).
